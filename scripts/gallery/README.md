# 图库（照片墙）

`gallery.html` 是站点的照片墙。它本身仍然是纯静态页面：只读一份 `assets/gallery/photos.json`，
不依赖任何线上服务。这里的脚本只跑在你自己的电脑上，负责把原片变成可以上架的成品。

## 两条路，选一条

### 一、网页上传（推荐）

```
npm install          # 第一次才需要，装 sharp 和 exiftool
node scripts/gallery/server.mjs
```

浏览器会自动打开 `http://127.0.0.1:8788`：

1. 拖一批原片（或整个文件夹）进去；
2. 填标签（逗号分隔）、相册名，城市留空就按 GPS 自动判断；
3. 相机时钟不对的话，"时间校正"填 `8`（UTC → 北京时间）；
4. 点「开始处理」，等进度走完。

图片写进 `assets/gallery/`，`photos.json` 自动更新。处理完 `git add / commit / push` 就上线了。

这个服务只监听 `127.0.0.1`，关掉窗口就停，不参与线上运行。

### 二、命令行

```
node scripts/gallery/build.mjs "D:/相册/2025国庆阿坝" --tags 风光,长曝 --album "四川省 · 成都重庆阿坝州"
```

常用选项：

| 选项 | 作用 |
| --- | --- |
| `--tags a,b,c` / `--tag a` | 这批照片共用的标签 |
| `--album <名称>` | 相册名，写进 JSON 的 `collection` 字段 |
| `--city <名称>` | 强制指定城市，跳过 GPS 判断 |
| `--shift <n>` | 相机时钟偏移小时数（相机是 UTC 就填 8） |
| `--dry` | 只跑压缩和水印，不写文件（看体积和速度） |
| `--force` | 已经在库里的也重新生成 |
| `--width <n>` / `--quality <n>` | 长边上限（默认 1600）/ 预压缩质量（默认 85） |
| `--watermark <s>` | 水印文本（默认 `www.zhengqiao.wang`） |
| `--exif <file>` | 用现成的 exiftool JSON 代替现读（没装 exiftool 的机器上用） |

## 处理一张照片时做了什么

顺序不能改，原因写在下面：

1. **读 EXIF** —— 拍摄时间、机身、镜头、焦距、光圈、快门、ISO、GPS；
2. **压缩到 1600px** —— `sharp` 按 EXIF 方向摆正后缩到长边 1600、JPEG q85（mozjpeg）；
3. **写盲水印** —— 把 `www.zhengqiao.wang` 嵌进这份**最终尺寸**的像素里；
4. **立刻读回来校验** —— 读不出或内容不对就整张跳过，不让坏图进仓库；
5. **缩略图** —— 另存一张 720px 的 webp 给列表用；
6. **落盘 + 记录** —— 写 `assets/gallery/<id>.jpg`、`<id>-t.webp`，更新 `photos.json`。

关键约束：**水印必须写在最终尺寸上，写完不能再缩放、裁剪或重编码**，否则水印会散。
所以第 3 步之后产物原样存盘，缩略图是从成品另存的第二份文件，不碰成品。

压缩后的图没有 EXIF（`sharp` 重新编码会丢掉），GPS 自然不会跟着图片泄露；
地点是作为 JSON 里的 `city` 字段单独存在的，想隐藏就改 JSON。

## photos.json 长什么样

```json
{
  "photos": [
    {
      "id": "2025-10-22-photo-01",
      "src": "assets/gallery/2025-10-22-photo-01.jpg",
      "thumb": "assets/gallery/2025-10-22-photo-01-t.webp",
      "w": 1600,
      "h": 1066,
      "city": "阿坝州",
      "date": "2025-10-22",
      "hasGps": false,
      "tags": ["风光", "四川"],
      "camera": "Panasonic DC-S1RM2",
      "lens": "28-105mm F2.8 DG DN | Art 024",
      "focal": "37mm",
      "f": "f/10",
      "shutter": "1s",
      "iso": "ISO 80",
      "collection": "四川省 · 成都重庆阿坝州",
      "source": "…sha256…"
    }
  ],
  "generatedAt": "2026-11-25T…",
  "watermark": "www.zhengqiao.wang"
}
```

想改什么直接改这个文件，不用重跑脚本：

- 没有 GPS 的照片城市是 `「待定」`，改成真实城市即可；
- 日期按相机墙上时间算，只到年月日，想调就改 `date`；
- `tags` 是数组，增删都行；
- `collection` 只是"这一趟"的名字，页面上不参与筛选；
- `source` 是成品的 sha256，用来判断"这张是不是已经在库里了"，别手改；
- 新增照片后记得把 `id`、`src`、`thumb` 三个字段对齐。

`id` 命名规则是 `日期-城市序号`，没有 GPS 又没指定城市时是 `日期-photo-序号`。

## 页面上怎么用

- 顶部三行筛选：**地点 / 年份 / 标签**，行内不换行，横向滚动；
- 三行可以组合，比如「阿坝州 + 2025」；
- 照片按日期倒序排成连续网格，3 列（≥1280px 4 列，手机 2 列），滚到接近底部才继续加载；
- 点开任意一张进灯箱：看拍摄地点、时间、机身镜头参数，点标签就直接筛这个标签。

## 常见问题

**水印会不会被读不出来？**
不会——写入后立刻读回校验，读不出就不落盘。但只要有人把图**缩放、裁剪、加滤镜、再压缩一遍**，水印就会散掉（这正是它的原理）。所以成品图不要再让别的工具处理一遍。

**图太大怎么办？**
`--width 1400` 或 `--quality 78` 能再小一些，代价是画质。目前这批 7 张：正片 3.9MB、缩略图 0.3MB。

**原片会被改动吗？**
不会。脚本只读原片，成品写到 `assets/gallery/`。原片存在哪里都可以，脚本不依赖它还在。

**某张图处理失败了？**
看提示：多数是「没有拍摄时间」（手机截屏、导出图常见）。在命令行加 `--exif` 也没用的话，
可以先用任意工具把拍摄时间补上，或者处理后在 `photos.json` 里手工加一条。

**能不能不用 node_modules？**
成品的 `assets/gallery/*` 和 `photos.json` 与依赖无关，页面只读 JSON。换电脑时把 `node_modules` 重装一遍就行。
